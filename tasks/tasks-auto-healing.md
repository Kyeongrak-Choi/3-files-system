## 2. 프로젝트 목표

승인된 PRD에 따라 소비 고민 코칭 API와 결정적 모의 LLM 의존 서비스를 구축하고, HTTP 429·타임아웃·연결 실패·5xx·반복 장애를 안전하게 재현한다. Monitor·Diagnosis·Recovery·Verification·Orchestrator·Notification 역할을 분리해 제한된 자동 복구, 독립 검증, 회로 차단, 에스컬레이션과 MTTD·MTTR 측정을 제공한다.

## 3. 작업 원칙

- PRD에 정의된 코칭 API와 Auto Healing 범위만 구현한다.
- 실제 LLM·결제·로그인·운영 데이터·운영 인프라는 사용하지 않는다.
- 각 기능 작업에는 실패 조건, 테스트·검증, 완료 증거를 포함한다.
- 작업 완료는 코드 작성이 아니라 테스트 통과와 실행 증거 확보로 판정한다.
- 모든 구현 작업은 승인 후에도 [ ] pending으로 시작한다.
- 승인되지 않은 임의 쉘 명령, 운영 데이터 변경, 허용목록 밖 서비스 조작은 작업에 포함하지 않는다.
- 작업 중 새로운 요구가 필요해지면 PRD 변경 여부를 먼저 검토한다.

4. 독립 Verification, 회로 차단, 안전 중단, 사건 로그는 축소하지 않는다.

## 11. 미결정 사항

현재 PRD의 실행 관련 미결정 사항은 없다. 다음 항목은 구현 중 변경이 필요할 경우 PRD와 작업목록을 함께 갱신한다.

- 모의 LLM의 구체적인 고정 문구
- 로컬 실행 포트와 환경변수 이름
- 팀의 실제 알림 채널이 존재하는 경우 Notification 출력 방식

위 항목은 기능 범위를 변경하지 않는 구현 결정으로 취급하며, 임의로 운영 기능을 추가하지 않는다.
