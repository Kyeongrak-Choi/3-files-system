# PRD: 지름막 소비 고민 코칭 Auto Healing

## 1. 문서 상태

- 상태: 초안
- 작성일: 2026-10-29
- 대상 서비스: 지름막의 소비 고민 코칭 API
- 구현 기술 후보: Python, FastAPI, Flutter, Docker
- 현재 단계: Day 1 PRD 작성

## 2. 문제 정의

지름막은 사용자가 사고 싶은 물건과 구매 이유를 기록하고 72시간 동안 소비를 숙고하도록 돕는다. 여기에 LLM 기반 소비 고민 코칭을 연결하면 사용자가 구매 전에 스스로 생각할 질문과 점검 결과를 받을 수 있다.

후속 후보로는 누적된 구매 고민 기록을 LLM으로 요약해 소비 회고 결과를 제공하는 구매 기록 요약 API를 고려한다. 이 후보 역시 LLM 사용량 초과·타임아웃·응답 형식 오류에 대한 Auto Healing 적용 대상이 될 수 있지만, 이번 3일 MVP의 주 대상은 소비 고민 코칭 API로 한정한다.

그러나 LLM API는 사용량 초과(HTTP 429), 응답 지연, 연결 실패가 발생할 수 있다. 이 의존 서비스의 장애가 코칭 요청 전체로 전파되면 사용자는 숙고 과정의 피드백을 받지 못하고, 운영자는 매번 수동으로 장애를 확인하고 복구해야 한다.

## 3. 목표

1. LLM 의존 서비스 장애를 자동 탐지하고 유형을 분류한다.
2. 허용된 범위 안에서 제한된 재시도 또는 대체 코칭 응답을 수행한다.
3. Recovery의 자기보고가 아닌 독립 Verification으로 정상화를 판정한다.
4. 반복 실패를 회로 차단하고 사람에게 에스컬레이션한다.
5. 장애 주입부터 복구까지의 사건 정보와 MTTD·MTTR을 보존한다.

## 4. 비목표

- 실제 결제, 주문, 금융 서비스 연동
- 실제 사용자 개인정보 처리
- Google·카카오 로그인 신규 구현 및 인증 장애 자동복구. 해당 로그인 기능은 기존 앱 구현을 유지한다.
- LLM의 임의 쉘 명령 생성·실행
- 운영 DB나 운영 인프라의 자동 변경
- 비용 한도 없는 리소스 확장

## 5. 대상 사용자와 사용 시나리오

### 대상 사용자

- 충동구매를 줄이고 싶은 사람
- 구매 전에 한 번 더 고민하고 싶은 사람
- 복잡한 가계부 없이 소비 습관을 돌아보고 싶은 사람

### 정상 시나리오

1. 사용자가 Flutter 앱에서 물건 이름, 가격, 구매 이유를 입력한다.
2. FastAPI 소비 고민 코칭 API가 요청을 접수한다.
3. 코칭 서비스가 LLM 의존 서비스에 숙고 질문·소비 점검 결과를 요청한다.
4. 정상 응답을 사용자에게 반환하고 사건·추적 정보를 기록한다.

### 장애 시나리오

LLM API가 HTTP 429를 반환하거나 타임아웃·연결 실패가 발생하면 Monitor가 사건을 생성한다. Diagnosis가 장애를 분류하고, Orchestrator가 정책과 시도 횟수를 확인한 뒤 Recovery를 호출한다. Recovery는 제한된 재시도 또는 사전 정의된 대체 응답을 수행한다. Verification이 헬스체크와 핵심 코칭 요청으로 정상화를 확인한다. 실패가 반복되면 회로를 차단하고 Notification이 사람에게 알린다.

## 5.1 후보 서비스

| 후보 서비스 | 설명 | 이번 MVP 포함 여부 |
|---|---|---|
| 소비 고민 코칭 API | 구매 후보·구매 이유를 바탕으로 숙고 질문과 점검 결과 생성 | 포함 |
| 구매 기록 요약 API | 누적 구매 고민 기록을 요약해 소비 회고 결과 생성 | 후속 후보, 제외 |

구매 기록 요약 API는 기존 구매 기록이 충분히 쌓인 사용자를 위한 확장 기능이다. 코칭 API의 장애 복구 흐름을 검증한 뒤 별도 사건 유형과 요약 결과 검증 기준을 추가한다.

## 6. 서비스 범위

### MVP 포함

- 구매 고민 코칭 요청·응답의 최소 API 흐름
- LLM 의존 서비스 모의 구현 및 장애 주입
- HTTP 429, 타임아웃, 연결 실패·5xx, 반복 장애
- Monitor, Diagnosis, Recovery, Verification, Orchestrator, Notification의 책임 분리
- 제한된 재시도, 지수 백오프, 회로 차단, 안전 중단, 에스컬레이션
- 사건·추적 ID, 시각, 근거, 복구 결과, 검증 결과 로그

### MVP 제외

- 실제 쇼핑몰·결제·금융 연동
- Google·카카오 로그인 신규 구현 및 인증 장애 자동복구. 기존 앱의 로그인 기능은 유지한다.
- 운영 데이터 변경과 실제 사용자 데이터
- 자동 결제 또는 구매 차단
- 운영 환경에서의 자동 설정 변경

## 7. 개념 아키텍처와 역할

```text
[Flutter 앱]
      ↓
[FastAPI 소비 고민 코칭 API]
      ↓
[Orchestrator]
   ┌──┼───────────────┐
   ↓  ↓               ↓
[Monitor] [Diagnosis] [Recovery]
                           ↓
                    [LLM 의존 서비스]
                           ↓
                    [Verification]
                           ↓
                    [Notification]
```

| 역할 | 책임 | 입력 | 출력 | 권한 제한 |
|---|---|---|---|---|
| Monitor | 상태·로그·지표 관찰, 사건 생성 | 헬스체크·오류·지연 | incident_id·증거 | 조회·사건 생성만 |
| Diagnosis | 장애 유형과 원인 후보 분류 | 사건·로그·시도 이력 | 분류·근거·복구안 | 복구 직접 실행 금지 |
| Recovery | 허용된 복구 실행 | 승인된 복구안 | 실행 결과·시도 정보 | 허용목록 행동만 |
| Verification | 복구 결과 독립 검증 | 복구 결과·핵심 요청 | 정상·실패 판정 | 검증 없는 완료 선언 금지 |
| Orchestrator | 순서·정책·상한·상태 관리 | 각 역할 결과 | 다음 호출·최종 상태 | 정책 우회 금지 |
| Notification | 사람에게 결과·승인 요청 전달 | 사건·검증 결과 | 알림·에스컬레이션 | 정책 변경 금지 |

## 8. 장애·복구 정책

| 장애 | 1차 대응 | 2차 대응 | 상한 | 완료 조건 |
|---|---|---|---:|---|
| HTTP 429·사용량 초과 | 지수 백오프 재시도 | 대체 코칭 응답 | 3회 | 핵심 요청과 응답 형식 검증 |
| 타임아웃 | 지수 백오프 재시도 | 대체 코칭 응답 | 3회 | 제한시간 내 정상 응답 |
| 연결 실패·5xx | 지수 백오프 재시도 | 테스트 모의 서비스 재시작 또는 에스컬레이션 | 3회 | 헬스체크·핵심 요청 검증 |
| 반복 장애 | 추가 자동 복구 제한 | 회로 차단·사람 에스컬레이션 | 3회 | 자동 실행 중단과 알림 확인 |

자동 실행은 테스트 환경의 허용목록 안에서만 수행한다. LLM 사용량 한도·요금제, 운영 라우팅, 운영 설정, 데이터 변경은 사람 승인 없이는 실행하지 않는다. 원인을 분류할 수 없는 장애는 자동 변경 없이 에스컬레이션한다.

## 9. 검증과 성공 기준

### 복구 성공

다음 조건을 모두 만족해야 한다.

- 헬스체크가 정상이다.
- 핵심 코칭 요청이 허용된 시간 안에 성공한다.
- 응답 스키마가 유효하다.
- 오류율과 응답시간이 실험 기준선으로 돌아온다.
- Verification 로그가 정상 판정을 남긴다.

### 측정 지표

- MTTD = detected_at - injected_at
- MTTR = recovered_at - injected_at
- 복구 성공률 = 자동 정상화 건수 ÷ 전체 장애 건수
- 평균 복구 시도 = 전체 시도 횟수 ÷ 성공 건수
- 에스컬레이션율 = 에스컬레이션 건수 ÷ 전체 장애 건수
- 회귀 테스트 통과율 = 통과 건수 ÷ 전체 검증 건수

### 필수 사건 정보

incident_id, trace_id, 장애 주입·탐지·복구·검증 시각, 탐지·진단 근거, 복구전략, 시도 횟수, 승인·에스컬레이션 결과, 독립 검증 결과, 최종 상태를 보존한다. 사용자 식별자, 토큰, 원문 구매 메모 등 민감정보는 로그에서 제외하거나 마스킹한다.
